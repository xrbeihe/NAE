# ANE 世界地图 — 生成逻辑与数学原理

> 地图是 Canvas 2D 渲染的纯前端功能，不需要后端参与。
> 代码入口：`frontend/index.html` 中的 `generateWorldMap()` 和 `frontend/public/worldmap.js`。

## 一、点位生成（Point Generation）

地图上的宗门位置由**随机散射（Scatter）**算法生成，以泊松圆盘采样（Poisson Disk Sampling）作为后备补充。

### 核心思路

在画布上放置 N 个点（宗门位置），要求任意两点之间的距离不小于一个最小值（`radius`），避免标签渲染时重叠。

### 算法流程

```
1. 计算 radius:
   radius = min(画布宽, 画布高) / sqrt(宗门数量) * 1.3

2. 随机散射（优先）：
   最多尝试 2000 次，每次在画布内生成一个随机点。
   如果新点与所有已有点的距离 >= radius * 0.85（代码实际值），则接受。
   否则丢弃重试。

3. 泊松圆盘采样（补充）：
   如果散射点数不足，用 poissonDisk() 生成补充点。
   Poisson 点与已有点的间距要求 >= radius * 0.55。
   从画布中心开始生长，最大 1000 点，30 次尝试/点。

4. Force-fill（最终填补）：
   如果仍不足，用最小间距 30px 强制填入剩余点数。
```

### 为什么不用纯 Poisson

Poisson Disk 从中心开始向外生长，容易导致点群集中在画布中央，边缘稀疏。随机散射 + 大间距检测的分布更均匀，且实现更简单。

### 宗门/城市数据来源

宗门名：`GET /sessions/models/sects`（从 `world_templates.json` 过滤，后缀匹配圣地/宗/门/宫/阁/殿/谷/观/派，NSFW 关键词过滤）
城市名：`GET /sessions/models/cities`（以"城"结尾，NSFW 过滤）
每个宗门名 + 城市名被随机分配到一个点位上。

## 二、标签碰撞处理（Label Collision Resolution）

所有宗门标签渲染前，先运行碰撞检测算法消除重叠。

### 算法：迭代式成对排斥（Iterative Pairwise Repulsion）

```
1. 为每个标签计算包围盒（bounding box）：
   宽度  = 文字宽度 + padding(6px) * 2 + 6
   高度  = 18 + padding * 2

2. 对每一对标签 (A, B)：
   检查包围盒是否重叠：
     overlapX = min(A.right, B.right) - max(A.left, B.left)
     overlapY = min(A.bottom, B.bottom) - max(A.top, B.top)
   如果 overlapX > 0 且 overlapY > 0：
     沿重叠较短的轴向推开：
       push = overlap + 2
       A 移 push/2，B 移 push/2，方向相反

3. 重复步骤 2 最多 5 次（pass，文档旧写 10 次，代码实际为 5 次），
   如果某次 pass 没有任何标签移动，提前终止。
```

### 数学原理

| 概念 | 说明 |
|------|------|
| **包围盒检测** | 轴对齐包围盒（AABB）碰撞检测。标签用矩形近似，检测矩形是否相交 |
| **最短分离轴** | 沿重叠较小的轴推开，移动距离最小，收敛更快 |
| **迭代收敛** | 成对排斥是迭代过程。推 A 可能造成 A 与 C 重叠，需要多轮迭代 |
| **阻尼项** | push = overlap + padding(2)，padding 防止相邻标签紧贴 |
| **终止条件** | 最大迭代次数 5 或 0 移动（已收敛） |

## 三、地图渲染层级

```
Layer 0: 地形（Terrain）
  6 层八度 fBm（分形布朗运动）单纯形噪声（文档旧写 5 层，代码实际为 6 层+）
  9 级调色板（深海 → 雪峰）
  海岸线辉光（Edge Detection + Brighten）
```

### 地形调色板

地图颜色由 6 层八度的单纯形噪声叠加（fBm）生成高度值 h ∈ [-1, 1]，
映射到 9 级调色板，相邻色阶之间线性插值平滑过渡：

| h 范围 | RGB 颜色 | 地形类型 |
|---------|----------|----------|
| ≤ -0.35 | `(15, 28, 60)` | 深海 |
| -0.35 ~ -0.15 | `(25, 60, 95)` | 浅海 |
| -0.15 ~ 0.10 | `(60, 100, 60)` | 海岸 / 沙滩 |
| 0.10 ~ 0.20 | `(80, 125, 65)` | 平原 |
| 0.20 ~ 0.30 | `(60, 100, 50)` | 森林 |
| 0.30 ~ 0.40 | `(100, 85, 55)` | 丘陵 |
| 0.40 ~ 0.55 | `(120, 95, 70)` | 山地 |
| 0.55 ~ 0.70 | `(160, 140, 120)` | 高山 |
| ≥ 0.70 | `(220, 210, 200)` | 雪峰 |

### fBm 参数（实际代码值）

| 参数 | 代码值 | 说明 |
|------|--------|------|
| scale | 0.002 | 噪声频率，代码值与文档不同（文档写 0.008） |
| octaves | 6 | 细节叠加层数（文档写 5） |
| persistence | 0.55 | 低频占比（文档写 0.6） |
| sea level offset | +0.15 | 海平面偏移，减少蓝色水域面积 |

### 海岸线辉光

对每帧浅海像素，检查 5x5 邻域内是否有陆地像素（非 Water），
是则提亮（R+25, G+35, B+20），形成海岸线的发光效果。

```javascript
const isWater = (x, y) => {
  // 深海/浅海判定：blue > red + 20 && red < 80
  return b > r + 20 && r < 80;
};
// 对每个 water pixel，检查 -2..+2 邻域
for (let dx = -2; dx <= 2; dx++)
  for (let dy = -2; dy <= 2; dy++)
    if (!isWater(x+dx, y+dy)) nearLand = true;
```

```
Layer 1: 城市标签（City Labels，底层）
  青色半透明圆角矩形，显示城镇名

  阴影效果（rgba(0,0,0,0.5) blur=6）
  边框：#5a9aaa，文字：#d4eef5

Layer 2: 宗门标签（Sect Labels，顶层）
  羊皮纸风格圆角矩形，显示宗门名
```

## 四、交互逻辑

| 操作 | 效果 |
|------|------|
| 鼠标滚轮 | 缩放画布（0.5x ~ 5x）—— 缩放时以鼠标位置为中心 |
| 鼠标拖拽宗门标签 | 单独偏移宗门层，露出下方城市标签 |
| 触摸拖拽 | 同上 |

**注意**：只有宗门标签层可拖拽，城市标签始终在原位。
缩放的是整个画布内容的视觉比例（不是 Canvas 尺寸），通过 `scale`/`offsetX`/`offsetY` 属性控制。

## 五、地图持久化

数据通过 API 前后端分离：

| 操作 | 做法 |
|------|------|
| 生成预览 | 前端独立完成，不依赖后端 |
| 保存 | `POST /sessions/{id}/map` → 存入 `session.map_data` + `session.world_intro` |
| 恢复 | `GET /sessions/{id}` → 取 `map_data` → `WorldMapRenderer` 重新渲染 |
| 二次恢复 | 已保存的地图对应按钮禁用（`map-faction-count` disabled, "随机生成"按钮 disabled）|

保存时附带 `world_intro`（世界简介），包含角色信息和势力、城市列表：

| 碰撞迭代 | 最多 5 次（代码值） | 文档旧写 10 次 |
