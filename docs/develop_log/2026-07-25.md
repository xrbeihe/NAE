## 1. 代码审查 — 发现并修复 5 个 Bug

### Bug 1 — HO 标记逻辑不一致
- `input_validator.py` 中 `nsfw_confirmed` 用 `user_input`（未 strip）做判断，而 HO 剥离用 `text`（strip 后）
- 当输入末尾有空格时（如 `"我要双修HO "`），HO 标记不生效但文本仍被裁剪
- **修复**：统一使用 `text`（strip 后）做判断

### Bug 2 — DB session 泄漏
- `main.py` 中间件把 `get_db()`（异步上下文管理器）写成 `async for db in get_db()`
- 异常被 `except Exception: pass` 吞掉，`request.state.user` 始终为 None
- **修复**：`async for` → `async with get_db() as db:`

### Bug 3 — pending_debut 作用域缺失
- `game_engine.py` 中 `pending_debut` 检查只遍历 `active_set.core_npcs`
- `load_model_data` 块注入的不在 active_set 内的 NPC，其 `pending_debut` 永远不会被清除
- **修复**：在 `load_model_data` 块内同步处理 `pending_debut`

### Bug 4 — 建模 prompt 参数传错
- `game_engine.py` 中 `f"人物性别：{player_name}\n\n"` 把玩家名写入了性别字段
- **修复**：改为 `f"人物性别：{npc_model.gender or '待确定'}\n\n"`

### Bug 5 — config.json 重复键
- `month_to_season` 键出现两次
- **修复**：删除重复行

### T3 截断事件分析

**原因**：无 HO 标记 → DeepSeek 不确定能否直白描写 → 用大量过渡文字绕圈子 → 触达 `max_tokens: 8192` → JSON 截断 → `json_repair` 修复失败 → LLM 重试（额外 4,065+1,760 tokens）。

**影响**：
- 浪费 **18,012 tokens**（占全部叙事 token 的 **99.1%**）
- 用户等待 **141.3 秒**
- 额外成本 **$0.00419**

**修复方案**：
1. 前端 HO 提醒（NSFW 关键词 ≥2 个且无 HO 时显示红色提示）
2. `json_repair` 处理截断 JSON
3. LLM 重试带格式提醒
