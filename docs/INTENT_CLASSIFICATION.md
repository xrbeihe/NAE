# ANE 意图分类系统 — 设计与维护指南

## 总览

意图分类是 `input_validator.py` 的核心功能。它决定 LLM 收到什么样的 Prompt——正常叙事、NSFW 色情描写、NTR 背德场景，还是战斗/travel/inspect 等其他意图。

**核心文件**: `backend/ane/modules/input_validator.py`

---

## 分类流程

```
玩家输入
  │
  ├── 安全检查（暴力/违禁内容）→ 阻断
  ├── 注入检测（Prompt Injection）→ 替换为 [内容已过滤] + 放行
  ├── 系统命令（/status /facts 等）→ 绕过叙事
  │
  ├── Step 1: 意图关键词匹配（INTENT_PATTERNS）→ 初步意图
  │     ↓
  ├── Step 2: 上下文降级（Context Exclusion）→ 叙事/第三人称场景降级回 dialogue
  │     ↓
  ├── Step 3: NTR 独立检测（ntr_patterns）→ is_ntr 标记
  │
  └── 输出: ValidationResult(intent, is_ntr, target_word_count, injection_detected, ...)
```


## 上下文降级系统

降级系统防止玩家聊到相关内容时被误判为 NSFW/NTR。

### 触发条件

满足以下任一：
1. 关键词匹配结果为 `nsfw` 或 `ntr`
2. `is_ntr = True`

### 降级模式

当输入匹配以下正则模式时降级为 `dialogue`：

| 分类 | 模式 | 示例 |
|------|------|------|
| 叙事信号 | 听说、据说、故事、记载、传说 | "听说那个长老被人背叛了" |
| 被动承受 | 被.{0,4}(背叛/出卖/绿/NTR) | "他被那个女修背叛了" |
| 第三方陈述 | 犯了.{0,4}(背叛/出轨)、因.{0,4}(出轨/背叛) | "他犯了背叛门规的大罪" |
| 已发生态 | (背叛/出轨).{0,4}(了/过/的/者/案/罪) | "这是一起出轨的案例" |
| 身份修饰 | 人妻/人夫.{0,4}(身份/长老/修士/高手/...) | "那位人妻长老修为很高" |
| 非性动作 | (继续/别停/用力/快点/慢点).{0,4}(走/跑/推/拉/搬/说/做/吃/喝/看/想) | "他让她快点走" |

### 强行保留（不被降级）

即使匹配了降级模式，以下情况**保留原始意图**：

| 模式 | 示例 |
|------|------|
| 干你、干她、干我 | "我要干她" |
| 操死 | "操死你" |
| 射进、插进、进入她、进入我 | "插进她的小穴" |
| 当着XX的面（第一人称） | "当着他老公的面干她" |

### Cultivate 排除模式

当修炼关键词出现在教导/描述/讲故事等被动语境时，降级回 `dialogue`：

```python
_CULTIVATE_EXCLUSION = re.compile(
    r'(?:教|教导?|指导?|指点?|让|叫|帮|替|为|给).{0,6}(?:修炼|修行|闭关)'
    r'|(?:修炼|修行|闭关).{0,4}(?:了|过|的|时|之|后|中|者|人)'
    r'|(?:讲|说|谈|聊|问|告诉|描述).{0,10}(?:修炼|修行|闭关)'
)
```

## 常见误判场景及原因

| 玩家输入 | 识别结果 | 原因 |
|----------|---------|------|
| "合欢宗的人继续折磨着他" | `nsfw` | 命中"合欢"关键词（NSFW列表）。因为匹配到的词是"合欢"而非"干/操/插"，**降级时没有被强行保留**。这是个误判 |
| "长老的鸡巴好大" | `nsfw` | "鸡巴"是 NSFW 关键词，即使第三人称也无法通过降级排除（降级模式没有覆盖性器官词+第三人称的组合）。这是个误判 |

## 注入检测策略

**重要变化**：检测到 Prompt Injection 后**不阻断**，而是替换为 `[内容已过滤]` + 继续放行。

```python
cleaned = re.sub(pattern, "[内容已过滤]", cleaned, flags=re.IGNORECASE)
```

覆盖的中文 + 英文注入模式约 30 条正则，包括：
- 忽略/忘记之前的指令
- 你不是叙事引擎
- 从现在开始你是XXX
- system prompt / DAN / jailbreak
- 输出/显示系统提示

## 如何维护与扩宽

### 添加新的 NSFW 关键词

在 `INTENT_PATTERNS` 的 nsfw 列表中添加：

```python
(["做爱", "上床", ...
  "新词", "新短语"], "nsfw"),
```

注意：添加的词会**匹配任何包含该词的输入**，包括第三人称叙事。如果添加了一个"性器官"级别的词（如"肉棒"），同时确认降级模式需要更新。

### 添加新的降级模式

```python
_non_nsfw_context = re.compile(
    r'(?:...'
    r'新模式|'       # 在这里加
    r')'
)
```

降级模式匹配后会检查**强行保留模式**（`_override`）。如果新关键词的误判场景仍然发生，可以考虑在 `_override` 中添加排除条件。

### 测试降级是否生效

```bash
cd backend && python -c "
from ane.modules.input_validator import validate
r = validate('测试输入')
print(r.intent, r.is_ntr)
"
```

## 设计原则

1. **宁可错判 NSFW，不要错放 NSFW** —— 误把正常聊天当成 NSFW 只会让 LLM 收到多余的色情素材，不影响使用；误把色情内容当成普通聊天，LLM 会拒绝描写
2. **关键词匹配是开发者的责任** —— `input_validator.py` 不做机器学习，不做语义理解，全靠关键词和正则
3. **降级系统是安全网，不是主逻辑** —— 每个新关键词都应该先确认降级系统能否处理它的叙事用法
4. **注入检测不阻断** —— 检测到注入模式后替换标记 + 放行，不破坏对话体验
5. **测试用例要有** —— 改完对着上面的测试表跑一遍
